## 1. 任务1：TB容差与无条件PASS清点（V9，只清点不改）

**范围**：全部TB与TB头文件，不含`legacy/`：
- 系统级：`rtl/ppg_control_top/tb_*.v`、`*.vh`；
- 芯片级：`rtl/ppg_chip_digital_top/tb_*.v`；
- 模块级：各模块目录下的`tb_*.v`。

另外，回归入口怎样判定通过，也在范围内：
- `rtl/ppg_control_top/run_xsim_regression.sh`；
- `rtl/ppg_chip_digital_top/run_xsim_regression.sh`；
- `tools/run_unit_tb_regression.sh`。

**要找的东西**：
1. **容差与宽松判据**：
   - 允许差额（"允许差1""最多少1笔""至少N"之类）；
   - `>=`、`<=`、`abs(...) <=`形式的比较；
   - 比合同规定更宽的时间窗口；
   - 只比较区间、不比较精确值的检查。
2. **无条件PASS**：不在任何判定分支内的`$display("PASS...")`；或者判定条件恒真。
3. **空真**：检查的前提场景根本没发生（例如事件计数为0），却仍打印PASS。要看检查有没有先确认场景确实出现过。
4. **看门狗与超时**：等待循环超时后只是静默退出，没有记FAIL，后续检查在错误状态下照样通过。
5. **回归脚本的判定**：
   - TB中途崩溃、提前`$finish`或没打印任何FAIL时，是否会被算作通过？
   - PASS行计数是否与预期数比较？

**已知项**（要包含在内）：
- PRC-05、PRC-08的无条件PASS引用行；
- AMI-24可能空真；
- long_10中"JNT前缀残留1笔"（TB计数口径）。

**每一项写出**：
- 位置：文件 + TB检查标签 + 附近的符号名。不要只写行号，行号会随修改漂移。
- 判据原文。
- 对照的合同或设计依据：合同文件与节号。
- 能否改成精确核算。
- 风险：它可能掩盖哪一类错误。
- 建议：只给建议，不改TB。

**输出**：`verification_reports/v9_v16/V9_TB_TOLERANCE_INVENTORY.md`。
- 先按类别（容差、无条件PASS、空真、静默超时、回归判定）和风险高中低给出汇总计数，再逐条列表。
- 风险判定为"高"的，单独列在报告开头。

## 2. 任务2：iverilog交叉检查试跑（V16，可选）

**前提**：你的环境能安装并运行Icarus Verilog（11或更新）。不能的话，跳过本任务，并在报告中写明。

**源码与参考结果**：
- 源码用分支`b-merge-batch`的提交`66bebdf`导出（`git archive`）。它的RTL/TB与`5d8ceba`相同，只差supervisor中的一行注释。
- 与它完全对应的xsim参考结果已提交在同一分支：`verification_reports/b_merge_batch_evidence/final_5d8ceba/`，共49个TB，Vivado 2022.2：
  - `index.tsv`：每个TB的PASS行数与`$finish`时刻；
  - `system/`、`chip/`、`unit/`下每个TB的`*.pass_sorted.txt`和`*.finish.txt`。

**方法**：
1. 按各回归入口的filelist编译每个TB：
   - 系统级：`rtl/ppg_control_top/run_xsim_regression.sh`中TB与`xsim_*_filelist.f`的对应表；
   - 芯片级：`rtl/ppg_chip_digital_top/run_xsim_regression.sh`；
   - 模块级：`tools/run_unit_tb_regression.sh`。
2. 编译注意：
   - 在Windows的Git Bash下，`-o <输出>`必须紧跟在`iverilog`之后、其它参数之前，否则会报出误导性的"-o: No such file or directory"。
   - 语言标准选能编过的最低版本，并记录。
3. 用vvp运行，把PASS行排序后与参考逐行比较，再比较`$finish`时刻。两个仿真器的时间单位与格式不同，比较前先换算成相同单位。
4. `tb_ppg_control_top_longrun`和`tb_ppg_control_top_long_10_cycles`仿真时长为10秒（约2000万拍），iverilog可能要跑数小时。时间不够就先跳过，标"未跑"。
5. 每一处差异归类：
   - 编译不兼容（工具问题）；
   - TB竞争（initial/always先后顺序、在同一时刻采样非阻塞赋值的旧值等）；
   - **RTL竞争**：例如时序always块中的阻塞赋值、多驱动、敏感表不全。这是本任务最重要的发现，要给出RTL符号和最小复现；
   - 仿真器语义差异：如`$random`、时间格式。

**输出**：
- `verification_reports/v9_v16/V16_IVERILOG_CROSSCHECK_TRIAL.md`：环境与版本、编译命令、逐TB结果表（编译/运行/PASS行比较/`$finish`比较/差异归类）、RTL竞争项详情；
- 脚本放在`verification_reports/v9_v16/scripts/`，正式RC1之后要再跑，所以要可复用。
