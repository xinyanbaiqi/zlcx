## 1. 真实端口总数与“185”的关系

- `ppg_control_top.v`端口列表位于`:94-293`，逐行读完：**165个端口 = 27 input + 138 output + 0 inout**。每个声明只有一个端口名，没有逗号多名声明，也没有跨行拆分的声明；端口列表以外没有其他`input/output`声明。
- 矩阵里的“C01 185”是§12.5中以`| C01 |`开头的**行数**，不是Top端口数。这185行名字互不重复（63 input / 122 output）。
- 两个集合逐名比对：**交集100个**；**85行不是Top端口**（全是C01合同连接表里点名的子模块端口，例如`i_active_config_valid`、`o_transaction_*`）；**65个真实Top端口在C01台账里没有行**。即 165 = 100 + 65，185 = 100 + 85。
- 事先提出的两种可能**都部分成立，但不能把差距解释成无害的口径差异**：
  1. “09-02之后RTL改过”：成立，但只涉及3个端口。V1.5（2026-09-05）新增的`o_s1_calibration_applied`/`o_s1_raw`/`o_s2_raw`没有台账行。
  2. “计数口径不同”：成立，而且是主因。原始抽取（批次开始前225行的那一轮）按C01合同文字里反引号标出的端口名抽取，所以混进了85个子模块端口名；合同只用散文或`<TXN_ID>`简写描述的AMI正式结果组、discard身份字段组等62个Top端口从来没被抽到（62个里59个在C01合同中0次字面出现，另3个只在散文里出现）。
  3. 结论：§12.1写的C01“at 185 ports”，以及“1803行每行都有真实grep+read生产者/接收沿引用”，对C01都不成立（见第2节的111条占位行）。**判定为真实台账缺陷，不是天然不1:1。**
